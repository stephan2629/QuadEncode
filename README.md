# Quad Encode

A study platform: search a topic, work through a ranked path of resources, take notes, and turn those notes into spaced-repetition recall prompts. See [CLAUDE.md](CLAUDE.md) for the full product and engineering spec.

Live: https://quadencode.netlify.app/

## Tech stack

| Layer | Tool |
|---|---|
| Framework | Next.js (App Router), TypeScript in strict mode |
| Styling | Tailwind CSS |
| Animation | Framer Motion |
| Database, auth, storage | Supabase (Postgres, with row level security on every table) |
| Deploy | Netlify, via the official `@netlify/plugin-nextjs` plugin |
| Testing | Vitest for unit tests, Playwright for end-to-end |
| AI | Gemini (primary), OpenAI as a fallback (`src/lib/ai.ts`) |
| Search / video | Serper (web search), YouTube Data API v3 (video and playlist lookup) |
| Icons | Lucide |

All third-party calls run server-side (Server Actions or `/app/api/` routes) so API keys never reach the browser.

## Using the app

1. **Search** a topic on the home page, signed in or not. Gemini turns the query into a subject and a ranked path of resources (free ones ranked ahead of paid), each checked for a live link before it's saved.
2. **Take notes** in the per-note markdown editor at `/notes/[id]`. Autosave is debounced, so you never have to think about saving; Cmd/Ctrl+S and the save-status pill force an immediate write if you'd rather not wait, and a failed save says so instead of quietly reporting "Saved".
3. **Mark up recall prompts** inline as you write:
   - `**Vocab:** term` / `**Def:** definition` becomes a flip card.
   - `**Quiz:** question` / `**A:** correct | wrong | wrong` (pipe-separated, first option is correct) becomes multiple choice.
   - Select any text and press Cmd+K (Ctrl+K on Windows) to turn it into a cloze card without leaving the editor.
4. **Import** existing material instead of retyping it: paste text, upload a PDF, or upload a screenshot. Imported material lands under an "Open questions" heading as prompts to fill in yourself.
5. **Review** at `/review` once at least one card exists (there's no review nav item before that). New cards show up first for a quick keep/edit/delete pass, then due cards on a Leitner schedule (box 0 through 5), capped at five cards a session. A missed card links straight back to the line in your note it came from.
6. **Practice** a single note's cards from its Practice tab, or play a quiz built from its content on the Quiz tab, neither of which touches the Leitner schedule. Both tabs appear once that note holds 10 or more vocab pairs or 10 or more quiz pairs; below that they aren't there. The "Generate 10 Quizzes & 10 Cards" button lives on the Notes tab (capped at 2 AI runs per rolling 24 hours) and is the quickest way over that line.

## Setup

```bash
npm install
cp .env.local.example .env.local
# fill in the Supabase vars, plus GEMINI_API_KEY, SERPER_API_KEY, and
# YOUTUBE_API_KEY for subject search/import/quiz generation to work.
npm run dev
```

Open [http://localhost:3000](http://localhost:3000).

AI calls (`src/lib/ai.ts`) try Gemini first, then fall back to OpenAI (`OPENAI_API_KEY`) if Gemini is rate-limited, overloaded, or unset, so one flaky key doesn't take down imports, quiz generation, or path search. OpenAI is optional; without it, those features just retry Gemini alone.

Database: run [supabase/schema.sql](supabase/schema.sql) in a Supabase project's SQL editor. It creates the tables in section 6 of CLAUDE.md and enables row level security on all of them.

## Scripts

- `npm run dev`: local dev server
- `npm run build`: production build
- `npm run lint`: ESLint
- `npm run typecheck`: `tsc --noEmit`
- `npm test`: Vitest unit tests
- `npm run test:e2e`: Playwright end to end tests (`tests/`)

Two suites need real Supabase credentials, because they sign in as a
throwaway user they create and delete themselves (email confirmation is on,
so a plain sign up never completes unattended): the row level security test
(`src/lib/notes-rls.test.ts`) and the note editor end to end spec
(`tests/notes-editor.spec.ts`). Locally they read `.env.local` and need
`SUPABASE_SERVICE_ROLE_KEY` in it; without it they skip. In CI they read
repository secrets and fail if those are missing, since a security test that
skips itself proves nothing.

Lighthouse has no script because it needs a production build running in a
second terminal, and one command that boots, audits, and tears down a server
is more fragile than two that don't:

```bash
npm run build && npm run start      # terminal 1
npx lighthouse http://localhost:3000/ --view    # terminal 2
```

Audit `/` and a `/study/[slug]` page. Targets are Performance ≥ 90 and
Accessibility, Best practices and SEO ≥ 95. Desktop currently meets all
four; mobile Performance sits at 77 to 78, held down by a pre-existing
simulated-mobile LCP on the landing page (Total Blocking Time is 0 ms). The
app routes are behind auth and Lighthouse cannot sign in, so check those by
hand for Total Blocking Time instead. Numbers and detail in
[docs/decisions/0009](docs/decisions/0009-note-editor-hardening.md).

## Deploy

Netlify, connected to this repo, using `netlify.toml` and the official `@netlify/plugin-nextjs` plugin. Push to `main` to deploy. All the env vars above (Supabase, Gemini, Serper, YouTube, and optionally OpenAI) need to be set in Netlify's site settings too (`.env.local` only covers local dev).

CI runs lint, typecheck, unit tests, build, and Playwright end to end tests on every push via `.github/workflows/ci.yml`. It also needs `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY` and `SUPABASE_SERVICE_ROLE_KEY` as repository secrets (Settings, then Secrets and variables, then Actions) for the two suites that sign in as a real user.

## Current state

**Phase 0 (foundations): done.** Repo, TypeScript strict mode, Tailwind, Supabase project with schema and RLS, Netlify deploy, CI pipeline.

**Phase 1 (auth and notes): done.** Sign up (with name), sign in, sign out, Google OAuth, password reset, account deletion, protected routes (`/dashboard`, `/notes/[id]`, `/review`) via `src/proxy.ts`. A dashboard for creating subjects and notes. A markdown note editor with debounced autosave, plus an inline PDF viewer when a note was imported from one.

**Phase 2 (cards and review): done.** `**Vocab:**/**Def:**` pairs become front/back flip cards; `**Quiz:**/**A:**` pairs (pipe-separated options, first is correct) become multiple-choice cards. Both are auto-extracted on save (`src/lib/parseBlanks.ts`, wired into `updateNoteContent`), matched as a pattern rather than an exact string so a dash works as well as a colon (`**Vocab -**`, `**Vocab-**`, `**Vocab:**` all parse). A plain line with no markup at all - `Term: Definition` or `Term - Definition` - also becomes a vocab card, scoped to text actually typed in the editor: pasted or uploaded source material lands under an `## Imported source` heading that the parser skips for this fallback, so a pasted article's ordinary sentences don't turn into accidental cards. A new card is skipped if another card in the same note already has the same definition. Cloze cards via selecting text and pressing Cmd+K or Ctrl+K (`createClozeCard`), or tapping the scissors button in the formatting toolbar - the same action, for devices with no keyboard shortcut to press. A Leitner scheduler (`src/lib/scheduler.ts`) with a binary Correct/Wrong rating, box 0-5, matching the section 8 interval table. The review screen (`/review`) offers a Flashcards/Quiz mode choice, shows box-0 cards first with Keep/Edit/Delete quality control, then due cards with instant-reveal Correct/Wrong or multiple-choice, capped at 5 cards per session, ending on a completion screen; a long answer shrinks through a few font-size steps instead of overflowing the card. A failed review's card carries a "Jump to note" link back to its source line. Three failures on a card append a new open Vocab/Def blank under `## Open questions` so the user re-explains the concept themselves. Quiz cards start life as `imported` tier (dashed, dimmed border, don't count toward progress); after two correct answers in a row, review prompts the user to re-explain the card in their own words and promotes it to `authored` tier, per section 4. The Review entry point on the dashboard only appears once the user has at least one card, per section 3. A vocab card in graded review is no longer a card you flip: it shows the term, asks you to type what you remember (Ctrl/Cmd+Enter, or the button, reveals), then shows what you wrote next to the real definition, the same write-then-reveal shape as the demo on the landing page. The reveal button is dead until something is typed, so a stray keypress can't hand over the definition before any retrieval happened, and the reveal itself still carries zero duration per section 13. Multiple choice and cloze cards are unchanged.

**Phase 2.5 (practice and local quiz): done.** The review completion screen shows correct/wrong counts plus missed prompts with jump-to-note links. A per-note Practice tab and a local Quiz tab (`src/lib/practice.ts`, `src/lib/quiz-parser.ts`) build questions straight from a note's own cards (vocab distractors are pulled from the note's other definitions), entirely on-device with zero AI calls, so they never write to the Leitner schedule and never touch the AI quota below. Both tabs save progress to `sessionStorage` as you go, so a mid-session tab refresh resumes where you left off instead of restarting; a "Start over" control clears it on purpose.

**Phase 3 (imports): done.** Paste text, upload a PDF (text extracted locally via `pdf-parse`, original file kept and shown in-note with zoom), or upload a screenshot; Gemini (`GEMINI_API_KEY`, server-only, OpenAI fallback) turns the material into Vocab and Quiz prompts. They land under a single `## Open questions` heading. Answers may be pre-filled directly (imports and AI generation are no longer required to leave them blank, a product decision documented in CLAUDE.md section 2); imported and AI-generated cards still start at `imported` tier and don't count toward progress until re-explained in the user's own words. Each import is recorded; an Imports history page appears on the dashboard after the first one. A note's AI-generated quiz can also be played on demand (`/notes/[id]`, Quiz tab) via a "Generate 10 Quizzes & 10 Cards" button that writes the `**Vocab:**`/`**Quiz:**` syntax straight into the note from plain prose, capped at 2 AI generations per rolling 24 hours per section 5 (`src/lib/quota.ts`), with remaining quota (and the wait time once exhausted) shown on the button. Source text sent to the model - a note's body, extracted PDF text, or pasted text - is capped at 12k characters (`capSourceText` in `src/lib/ai.ts`) before it's sent, so a long import doesn't spend tokens on more material than a batch of cards needs.

**Phase 4 (discovery and paths): done.** LLM-interpreted subject search on the public home page, usable signed out (`/study/[query]`). Serper for web results, YouTube Data API for videos and playlists. Real video/playlist ids are extracted in code (`src/lib/youtube.ts`) rather than left for the model to guess, sorted newest-upload-first for every subject so a search always surfaces current information. A query naming a certification whose official name uses "+" (Network+, Security+, A+...) is normalized before it reaches either search API, so typing "Network Plus" still finds the "Network+" material instead of returning weaker results for a phrase nobody actually published under (`normalizeCertPlus` in `src/lib/certQuery.ts`). Every candidate resource is checked for a live response (`src/lib/link-checker.ts`) before a path can be saved; broken links are discarded, not shown. Free resources are sorted ahead of paid in code, not left to the model's word. A query naming a certification or exam (a CompTIA exam, AWS Solutions Architect, and so on) gets a staged, multi-part path instead of one flat list, free-first within every stage. Saving a path or acting on it (`src/app/dashboard/actions.ts`) prompts sign-in for signed-out users. `/study/[query]` is genuinely ISR-cached now (`x-nextjs-cache: HIT`, `Cache-Control: s-maxage=604800, stale-while-revalidate=...` under a production build), but getting there took three attempts and the first two were both wrong. A cookie-reading Supabase client and an over-broad middleware matcher (`src/proxy.ts`) were both real bugs (fixed: SEO bookkeeping uses a cookie-free client, `src/utils/supabase/public.ts`; the matcher only runs on routes it actually branches on) but neither was why ISR wasn't caching the page. The actual cause (`docs/decisions/0008`): the route had no `generateStaticParams`, and a dynamic segment page without one never registers with Next's ISR system at all in this Next version, regardless of the `revalidate` export - confirmed by isolated testing, not by reading the export and assuming. Adding `generateStaticParams() { return [] }` to `page.tsx` was the actual fix. A `path_cache` Postgres table (`src/lib/pathCache.ts`, `docs/decisions/0006`) backs this up independent of ISR: a subject's Serper + YouTube + Gemini + link-check pass (measured at 21.5s in production) runs once, then every visitor for 30 days gets served from a single Postgres row, in every environment including `next dev` where ISR doesn't apply at all. The public "Try a different path" retry (capped at 3 tries per query per browser via `localStorage`) bypasses and overwrites that row, then calls `updateTag`/`revalidatePath` (`next/cache`) so the newly-cached ISR page reflects the retry immediately rather than serving the pre-retry version for up to 7 days. A query naming a certification now gets one fixed answer instead of AI ordering (`src/lib/certShape.ts`, `docs/decisions/0010`): the official vendor exam page, then one training course card holding both versions of the same course behind a Free/Paid selector (free on YouTube, paid on Udemy, free selected first, and either version rejected outright if it isn't on the right platform); saving the path saves the version the learner picked and drops the other, then exam prep material from the vendor's own domain or Udemy and nowhere else, free first so an official free practice-question set outranks a paid practice exam (Network+ and Security+ ship with CompTIA's own free question pages, checked live; A+ has no equivalent page so it doesn't get an invented one). A certification taking more than one exam gets a training course card per exam, so CompTIA A+ offers the Messer/Dion choice separately for Core 1 and Core 2. That shape is applied in code after generation, the same way the free-first rule is a sort rather than a prompt instruction, so a resource the model labelled wrong or left unlabelled is dropped or re-inferred instead of shipped. Detection covers the full CompTIA line plus AWS, Azure, Google Cloud, Cisco, PMI, ISC2, ITIL and a few more, and falls back to the vendor when a query names one without naming an exam (a bare "CompTIA" search used to match nothing and get a flat path with a retry button), and it matches the slug the home page actually produces ("CompTIA Security+" arrives as `comptia-security`, with the `+` gone) - the old hardcoded-path regexes matched on that `+` and so never fired for the query they were written for. Reddit, Quora, forums, and exam-dump sites are dropped from every path, certification or not, before the link check runs rather than after. Certification paths lose the "Try a different path" button, since there is nothing to retry into; skills and subjects keep it. Staying current is enforced rather than hoped for: `newestExamVersionFirst` reads exam codes out of candidate titles and prefers the higher number when two candidates name the same exam (SY0-701 over SY0-601, 220-1201 over 220-1101), which is what stops a search engine's fondness for a retired course from putting it in the path, and certification paths cache for seven days instead of thirty. No table of current exam codes is kept, since that would need editing every time a vendor refreshes an exam. The three pinned CompTIA paths are the exception and still need a human when an exam code turns over. The path itself now reads down a single rail with full-width cards instead of alternating sides: the old `md:odd:flex-row-reverse` took its parity from `nth-child`, so the step headings between cards shifted it and everything clumped onto one side. Professor Messer's courses now link to his YouTube playlists for the current exam codes rather than professormesser.com, and Udemy's 403 to server-side fetches is treated as live by `checkLinkStatus` (a dead Udemy URL still 404s), without which every paid course option would have been dropped by its own link check. `path_cache` rows are keyed `v2:<slug>` so the 30 days of rows written in the old shape read as misses instead of being served. The same version rides on the `localStorage` copy a retry leaves behind in the visitor's own browser, which was the more damaging of the two: that copy overwrote the server's path on every later visit with no expiry, so anyone who had retried a certification kept seeing their old path no matter what shipped. Certifications now read no local override at all and clear any left over. Searching also keeps the `+` in the slug as the word "plus" (`comptia-security-plus`), so the URL still names the exam and "A+ certification" doesn't arrive as `a-certification`. A certification result also carries a "Where this leads" block above the path (`src/lib/certCareers.ts`): the job titles the vendor itself names, which exam usually comes next, and a link to that vendor's own career pages. It's a static map keyed by the same certification ids the rest of `certShape.ts` uses, not a second live lookup, so it renders for the pinned CompTIA paths that skip the pipeline entirely and for every cached path with no schema change. A certification with no entry shows no block rather than an invented one, and a subject search never shows it at all. Searching "CompTIA trifecta" (or just "CompTIA", which names no single exam) returns one path called **CompTIA Trifecta** that walks A+ then Network+ then Security+ in order, each with its own official exam page, its free/paid training course, and its practice material, so the step headings read "Training course (CompTIA Network+)" rather than three unlabelled runs of the same words. It is composed in code from the three pinned single-exam paths (`src/lib/certPaths.ts`) instead of being written out a fourth time, so a Messer playlist that moves or an exam code that turns over is still one edit.

**Phase 5 (polish): mostly done.** The dashboard, notes editor, path finder, and landing page have responsive layouts, accessible keyboard/touch controls, reduced-motion handling, and production E2E coverage. Path-cache writes are server-only, path regeneration is not exposed in the interface, and the dashboard’s path limit is enforced in Postgres. Notes accept typed content, pasted text, PDFs, DOCX, text files, and images; ten unique vocabulary pairs unlock note-scoped flashcards and quizzes. AI imports are limited to three per subject per rolling 24-hour window, while quiz sessions have their own three-per-subject rolling limit. **Visual audit and UX fixes:** Landing page root background corrected from `#0a0908` to the spec's warm near-black `#14120f` (nav blur overlay, hero flip-card surface, and photo banner gradient fade updated to match); example chip touch targets keep their `min-h-[44px]` at all breakpoints after a `sm:min-h-0` override was removed. Logout on the home page is now instant: `setUser(null)` runs first so the nav reverts to "Sign in" synchronously, then the client-side Supabase session is cleared, and the server action runs without blocking the UI.

**Pre-launch hardening (note editor): done.** The note editor's autosave used to run a full card reconciliation on every save, including the prose-only edits that make up most typing, and that reconciliation issued one write per card sequentially (20 round trips after an AI generation pass). Text persistence and card syncing are now separate: `haveBlanksChanged` (`src/lib/parseBlanks.ts`) compares the parsed card syntax between the last saved body and the new one, and `updateNoteContent` skips the sync entirely when nothing card-shaped changed, so a prose autosave is one `UPDATE` and zero card queries. What sync remains is batched into one insert plus one upsert run concurrently. A partial unique index on `cards (note_id, line)` for basic/vocab types (cloze cards are meant to share a line, so they're excluded by the predicate) makes a double-insert impossible rather than merely unlikely if an autosave and a manual save overlap; the insert path catches the conflict, re-checks which lines still need a card, and retries once. Every save path (autosave, Cmd/Ctrl+S, title blur, cloze creation) now reads the server action's return value instead of reporting "Saved" regardless, so a failed save shows a red "Save failed" pill and a toast naming what happened, and doesn't advance the saved-content baseline. Note bodies over 500k characters are rejected with a message rather than truncated. The Three.js background (`@react-three/fiber` and friends, a `requestAnimationFrame` loop running on every route including the editor) is gone, replaced by a static CSS gradient at the same blur and opacity: it violated section 13's ban on ambient animation and cost bundle size and Total Blocking Time everywhere. `@tiptap/pm`, imported nowhere, went with it, 67 packages in total. Row level security is now proven rather than assumed (`src/lib/notes-rls.test.ts`): the note server actions do no ownership check of their own, and that test signs in as two users to confirm one can't read, update, or add cards to the other's note, plus that the owner can, so the blocked cases can't pass against a merely broken client. `getNote` selects explicit columns instead of `*`. The note editor's Practice and Quiz tabs now appear only once that note holds 10 or more vocab pairs or 10 or more quiz pairs (counted separately, so six of each doesn't qualify), animating in when the threshold is crossed; below it they're absent, not disabled. The AI generation button moved from inside the Quiz tab to the Notes tab, since gating the Quiz tab behind 10 quizzes would otherwise have hidden the only control that creates them. A new Playwright spec (`tests/notes-editor.spec.ts`) covers the main path: type a Vocab/Def pair, let autosave fire on its own, confirm the card is created exactly once and the text survives a reload. Two icon-only back links that had no accessible name got one. A readability pass across the app, measured rather than eyeballed: Tailwind's default `gray-500` is built for dark-on-light and lands at 4.12:1 on the page background and 3.87:1 on a card, both under the 4.5:1 WCAG AA needs, and it was the text colour in 74 of its 75 uses in `src/`. It's retuned once in `globals.css` (`--muted`, `#858c99`, 5.88:1 and 5.53:1) rather than edited at 74 call sites, so a new component using `text-gray-500` is legible by default. `font-light` (300 weight) came off the 24 places it sat on 12-14px text, where it thins the strokes exactly where they're already small, and stayed on large display text where it's a deliberate choice. The 44 `text-[10px]` labels went to 11px, and a path resource's description (the actual reading content of that page) to 16px with `max-w-prose` holding the line length near 65 characters. The landing page now presents both ways into the app at the same size instead of leading almost entirely with subject search: "Find a path" (the search box, which still works signed out) and "Just start studying" (open a note and write, paste, or upload). Someone taking notes for a class shouldn't have to search for a path first. A footer (`src/components/ui/Footer.tsx`) sits on the landing page, `/study/[query]`, and the dashboard, but not the note editor or the review screen, since section 15 wants one screen doing one job and anything visible during recall that isn't the prompt is an escape hatch. On the dashboard it goes inside the scroll container rather than beside it: the page root is `h-dvh`/`overflow-hidden`, so a footer outside would pin itself to the bottom of the viewport as a permanent bar. Every link in it points at a route that exists (no privacy or terms page has been written, so neither is listed rather than shipping a dead link), and the three subject links double as a crawlable way into the `/study` pages that section 16 exists to make indexable.
